# 缓存复用、图片去重与幂等

图片去重限制重新选图，缓存复用已有生成结果，业务幂等防止重复发奖；三者的身份、有效期和清理方式不同。发送与结算语义见 [项目架构](architecture.md#发图送达状态)，测试入口见 [测试与回归检查](../dev/testing.md#缓存复用与去重回归)。

## 1. 存储与有效期总览

`data_dir` 指 `StarTools.get_data_dir("astrbot_plugin_get_px")` 返回的插件数据目录，不是源码目录下的 `data/`。

| 内容 | 存储 | 身份／范围 | 有效期或更新条件 |
| --- | --- | --- | --- |
| 正式图片使用与预占用 | `image_index.sqlite3` 的 `image_usage` | 日期、会话、图源／标签、原始图片 ID | 最近 `dedupe_days` 个北京时间自然日；0 关闭 |
| Pixiv 数字分页起点 | 同库 `source_page_cursor` | 会话、图源／标签 | 距更新时间超过 3 天读取重置；正式取图按上游下一页 offset 更新，耗尽重置为 0；完整推荐参数仅在请求内保存 |
| 签到卡 JPEG | `checkin_card_cache/YYYY-MM-DD/<key>.jpg` | 用户、日期、主题、展示数据、背景、画质、实际安全规则 | 只保留当天日期目录 |
| 签到背景摘要 | 同目录 `<key>.json` | 当天基础记录定位的安全规则变体 | 与卡片一起按日期过期 |
| 日历 JPEG | 同一 `checkin_card_cache` | 用户、当前日期、目标月份、记录／事件摘要、画质、会话策略 | 只保留当天日期目录，即使查看历史月份 |
| 签到奖励、问候与基础背景 | `checkin.sqlite3` 的 `checkin_records` | 用户、北京时间日期 | 正式历史数据，不按图片缓存 TTL 删除 |
| 预览／刷新近期选图列表 | `_checkin_preview_background_ids` 内存字典 | 用户 ID，不按群拆分 | 5 分钟，最多最近 20 条；下次选图时淘汰 |
| 下载原图 | `temp/get_px_*` | 每次下载独立文件 | 通常用后删除；不确定的 OneBot 提交保护 600 秒 |
| 节假日数据 | `holiday_calendar.json` 及内存状态 | 年度日期数据、插件版本 | 初始化检查刷新条件：版本、年份、180 天成功间隔、24 小时失败重试窗口 |
| 黑名单缩略图 | `image_blacklist/thumbs/<id>.jpg`，关联同库 `image_blacklist` | 作品 ID | 无自动 TTL；更新替换，删除黑名单时清理 |

## 2. 正式图片去重

### 2.1 索引身份

入口：[`pixiv/search.py`](../../pixiv/search.py) 的 `_event_scope()`、`_source_key()`；存储：[`pixiv/index.py`](../../pixiv/index.py) 的 `ImageIndexStore`。

- 群聊 scope 为 `group:<群ID>`，同群不同用户共享使用记录。
- 私聊 scope 为 `private:<用户ID>`，不同私聊用户隔离。
- source_key 区分图源和标签，例如 `lolicon:search:alpha`、`lolicon:random`、`pixiv:search:alpha`、`pixiv:recommended`。标签去掉首尾空白并 casefold，除此之外不同标签不合并。
- 数据库主键是 `(date_key, scope, source_key, illust_id)`；查询和占用覆盖整个有效自然日窗口。
- `user_id` 和 `feature` 是记录字段，不是当前去重查询的跨会话汇总条件。
- `normal`、`normal_pending`、`checkin`、`checkin_pending` 不划成互不相干的池；相同 scope/source_key/illust_id 下，预占用和已用记录都阻止新选图。
- 去重按原始图片 ID，不计算图片字节哈希。Lolicon 的 ID 为 `PID:页码`，Pixiv 搜索／推荐通常为裸 PID；这两种表示当前不会合并。背景恢复时选取具体页会使用页码限定 ID。

因此，跨群、群聊与私聊、跨标签、跨图源、不同 ID 的相同图像，均不保证去重。这里没有用户全局或所有群全局的背景历史池。

### 2.2 时间窗口与清理

- `dedupe_days=1`：北京时间当天。凌晨跨天后，昨天的图片不再参与去重，不是滚动 24 小时。
- `dedupe_days=N`（2–7）：今天加之前 N−1 个自然日。
- `dedupe_days=0`：读取已用列表为空、占用直接放行、使用记录不落盘，并清空 `image_usage`；黑名单、安全词和分页游标不随之清空。
- 初始化应用配置并清理过期记录；普通 `/p` 请求也会校准索引的运行时天数。
- 记录、占用、释放会检查是否需要清理，每小时最多触发一次。即使物理旧行尚未删除，查询也不会使用窗口外的行。
- 缩短窗口会清理超期记录；再扩大窗口不能恢复已删除的历史。签到和刷新使用已初始化索引的天数，配置变更后应保存并重载插件。

### 2.3 调用链与占用状态

```text
/p、自然语言发图
  → _fetch_source_candidates → _pick_illusts
  → get_used_illust_ids → claim_usage(normal_pending)
  → 下载／构建／发送 → record_usage(normal) 或 release_usage(normal_pending)

首次签到、恢复失败后的背景重选、刷新背景
  → _prepare_checkin_background → _download_checkin_pixiv_background
  → _checkin_background_used_ids → claim_usage(checkin_pending)
  → 编码／持久化／渲染／发送 → _record_checkin_background(checkin)
  → 未完成选图或异常路径按业务层规则释放 checkin_pending
```

- `claim_usage()` 通过 SQLite `BEGIN IMMEDIATE` 查询并写入，防止同范围并发请求选中同图。只在选图后补一条记录不足以提供这层保护。
- 普通发图调用正常返回或发送超时后记录使用；其他发送异常与提交期间取消保留 pending，不扣费、不重发。下载／构建失败和构建期间取消释放未提交占用。
- 正式签到与付费刷新正常返回或发送超时后保留背景、卡片和占用；送达未知或提交期间取消也保留已保存背景、卡片及 pending，不标为发送成功、不补发。确定构建失败或提交前取消才释放新背景 claim；不自动退款或撤销已保存的购买记录。
- release 只删除符合指定 pending feature 的记录，不能用释放操作删除已经晋升的成功使用记录。
- pending 没有独立 10 分钟过期机制，随 `dedupe_days` 过期；600 秒只保护临时文件读取。

### 2.4 刷新、预览与日历的区别

| 入口 | 正式索引读取 | 正式占用／记录 | 额外规则 |
| --- | --- | --- | --- |
| `/p`、自然语言发图 | 是，去重开启时 | 是 | 首批全过滤／已用也补取；超限／下载失败释放 pending 并换图；最多 3 轮取源、20 张下载尝试，不足时发送已有图片 |
| 首次签到／背景重选 | 是 | 是 | 候选页无可用竖图时继续尝试；无可用作品则占位图 |
| `/刷新背景` | 是 | 是 | 近期用户列表、变化的选图 seed；拒绝与当天基础背景原始 ID 相同的候选；无新背景不扣费 |
| `/签到管理 预览` | 是 | 否，`claim_usage=False` | 近期用户列表，预览不消耗正式池，不写签到奖励或群榜 |
| `/签到日历` 背景 | 是 | 否 | 优先未用图，全部用过则允许复用；不占去重池 |
| `/签到主题 查看` | 否 | 否 | 发送内置静态预览图，不取在线背景、不调用 T2I |

表中正式占用／记录受 `dedupe_days` 控制；关闭时不保存图片使用记录。管理员预览不产生图片占用，使用请求内独立分页状态，不读取或推进正式持久分页起点。

预览与刷新共用 `_checkin_preview_background_ids`：按用户保存原始 ID，最多 20 条、5 分钟，可能临时跨群排除近期图，但不是持久的跨会话去重承诺。进程重建后列表消失。多个背景标签会随机排列，逐个尝试，正式使用记录仍按最终标签分池。

持久分页表只缓存数字起点，不缓存搜索结果。Lolicon 每次重新随机请求，不读取或推进分页表；历史 Lolicon 游标行保留但不参与取图。Pixiv 无论首选或回退，正式请求首次读取相应 source_key 的起点，随后使用请求内真实 continuation，保留推荐的收藏游标与已浏览／书签作品列表；列表参与重复位置比较并透传给 SDK，不只校验后丢弃。当前候选耗尽时按上游下一页 offset 保存数字起点；无下一页重置为 0，但本次请求不绕回首页。预览／刷新不读取或推进持久游标。

完整推荐 continuation 不跨请求保存；重启或下次请求仍只有数字 offset，不保证恢复完全相同的推荐位置。响应没有下一页与 offset=0 是两件事。`min_bookmark_id_for_recent_illust` 接受非负整数，`max_bookmark_id_for_recommend` 接受非负整数及精确的 `-1`，按上游边界原样传回，不因 `0`／`-1` 删除参数或返回首页；offset仍只能非负，作品ID列表仍只能正数。空页有 continuation 时保留续取状态，并按优先级尝试另一源；同一请求中重复 continuation 被拒绝。3 轮取源包含首轮，每轮最多请求两个来源，下载与补取共享既有时间预算。

## 3. 签到卡与背景摘要缓存

入口：[`checkin/application.py`](../../checkin/application.py) 的 `_handle_checkin()`、`_checkin_card_cache_key()`；缓存读写：[`checkin/cache.py`](../../checkin/cache.py)。

### 3.1 缓存身份

JPEG key 是 SHA-256，输入包括日期、用户、主题模板版本及规范化 view model。view model 包含奖励与成长快照、昵称、问候、称号、背景署名与 ID、背景来源／模式、头像 URL、刷新价格、渲染档位、JPEG 质量、背景画质、资源版本和实际安全规则。

- 运行时签到路径使用实际生效的普通分级开关、屏蔽词与黑名单快照，不把群号或私聊会话标识加入这份安全指纹。
- 同一用户相同条件下，规则相同的群可以共享当天卡片；规则不同则分别查找或生成变体。
- 安全服务一次解析配置，固定实际分级、全局匹配模式、全局＋分组词和作品 ID；选图与缓存身份使用同一快照。
- 关键词或匹配模式变化会改变有效规则指纹；没有内置词开关或未生效独立列表。
- 身份主要来自展示字段和版本，不是原图／头像内容哈希；同一 URL 或自定义路径下替换文件，不保证使已有 JPEG 失效。

### 3.2 基础记录与变体摘要

`checkin_records` 保存当天唯一奖励、问候和基础背景。背景摘要是派生缓存，不取代基础记录。

摘要 JSON 只有 `mode`、`source`、`illust_id`、`title`、`author`、`quality` 六个字符串字段，原子写入；不保存原图路径或完整作品元数据。

重复签到先用基础记录、主题、档位及安全规则定位摘要，再按摘要中的实际背景定位 JPEG，使图片和外发署名保持一致。规则变化后背景恢复／重选产生的变体不覆盖当天基础背景与基础画质。

### 3.3 命中、重建与过期

- 命中有效 JPEG 时不下载背景、不下载头像、不调用 T2I；只复用卡片并发送。
- JPEG 必须通过格式、尺寸和完整性检查；拒绝时删除该派生文件后重建。
- 摘要缺失／损坏或 JPEG 未命中时，重复签到尝试恢复当天基础背景；不保证仍恢复到已丢失摘要中的变体背景。
- 在线恢复需要可用的作品详情和下载链路；Lolicon 保存背景恢复也可能需要 Pixiv token。恢复失败重新选择合规背景，仍失败才用占位图。自定义背景恢复失败保持占位图，不按这个分支重选在线作品。
- `CheckinCardCache.store()` 在同一实例内对相同日期／key 加锁，锁内再次读缓存，避免重复渲染；不同实例不共享锁。JPEG 与摘要都原子发布，过期清理跳过本实例的活跃写入日期。
- `retention_days=1` 是卡片缓存固定默认值，与配置 `dedupe_days` 无关。初始化强制清理，随后读取／存储时按天清理过期目录；不是凌晨定时删除任务。
- 重启不会整目录清空当天缓存；过期 JPEG、摘要和临时写入文件按缓存规则清理，不清空数据库或备份。

## 4. 日历缓存

入口：[`checkin/commands.py`](../../checkin/commands.py) 的 `_handle_checkin_calendar()`，使用同一 `CheckinCardCache`，不复用签到卡的 key。

key 包括：当前北京时间日期、用户、目标月份、日历模板版本、月内 `(签到日期, coins_reward)` 摘要、本次实际事件 `(开始日期, 结束日期, 名称, 是否放假)` 快照（节气、节假日与自定义事件）、背景画质、输出尺寸，以及 `ContentSafetyPolicy.cache_identity()`。

- 该策略身份与签到卡一致，只包含实际规则，不包含 UMO／群号；同一用户相同实际规则与其他条件可共享日历缓存。
- 当天查看相同月份与条件命中时不取背景、不渲染。
- 当月新增签到或改变纳入摘要的奖励、实际事件内容变化（含备份导入修改名称／日期与在线节假日刷新）、画质／尺寸／策略或模板版本变化，会改变 key。
- 不是签到记录所有字段的完整哈希；刷新签到背景或只改不参与摘要的字段，不保证改变日历 key。
- key 与渲染共用一次事件收集的快照；缓存命中仍收集事件以检查变化，但不取背景、不调用 T2I。仅改磁盘节假日文件而未更新运行时数据，不会影响当前实例。
- 日历背景不写使用记录；缓存失效后可以重新取另一张氛围背景。无缓存时直接渲染，用后清理。
- 日历 JPEG 按生成当天日期保留，不按目标月份保留。

## 5. 操作对复用的影响

| 操作 | 结果 |
| --- | --- |
| 同日重复签到 | 复用当天问候、奖励快照及当前规则对应的卡片，不重奖 |
| 同用户跨群且有效规则相同 | 可共享当天签到卡，与正式选图去重的会话隔离并不矛盾 |
| 同用户跨群且规则不同 | 生成／读取各规则变体；返回原群在摘要与 JPEG 有效时可复用原卡 |
| 修改实际安全词、黑名单或普通分级 | 有效安全指纹变化，重新校验／选图，不复用旧规则 key |
| 刷新背景成功 | 事务内扣费并更新当天基础背景与余额快照，再渲染；旧使用记录不清除 |
| 购买／切换主题 | 更新用户偏好和当天主题／模板版本；后续签到按对应 key 查找或生成，不主动删除所有旧 JPEG |
| 只修改卡片画质配置 | 普通重复签到保持当天记录档位；管理员预览与刷新立即用配置；日历直接用当前配置 |
| 修改问候配置或成员当前数值 | 已保存问候及奖励快照不自动重写；不保证改变当天卡片 |
| 刷新背景，一言模式 | 重新请求一言，成功保存；失败保留原句；AI／本地模式不自动刷新问候 |
| Pages 清理缓存 | 删除卡片／日历 JPEG、背景摘要和超过保护期的下载图；下次按需重建，不重奖 |
| 修改模板文件 | 内存模板不按文件 mtime 自动失效；需重新加载模块或重启，并同步模板版本以避免旧 JPEG 命中 |

缓存 key 改变通常意味着旧文件不再匹配，不代表立即物理删除。切回相同内容身份时仍可能命中保留的当天文件。

## 6. 发奖与资料幂等

入口：[`checkin/record_store.py`](../../checkin/record_store.py)、[`checkin/omnidraw_bridge.py`](../../checkin/omnidraw_bridge.py)。

- 签到按 `(date_key, user_id)` 保存唯一记录，同一用户每天全局只发一次金币和好感度；发送失败不会因此重新发奖。
- 群榜存在 `(date_key, group_id, user_id)` 记录；重复签到只更新该群记录，同日可进入多个群榜。
- 问候存在当天签到记录中：已有问候直接返回，重复签到不再次调用远程模型。一言／AI 失败先使用已持久化本地文案，不在每次重复签到重试升级。
- 清理 JPEG／JSON 不清空签到记录，重建图片不重新发奖。
- 万象画卷通过对方运行时 `checkin_at` 防重复发签到额度；对方归一化每日统计负责跨天清零。本插件使用真实桥接状态，不缓存一份可无限复用的额度快照。
- QQ 生日是正式用户资料：手动来源或 `qq_birthday_checked` 已完成时不自动再查；明确响应后记已检查，超时／异常不记完成。清除生日重置检查标记，手动查看在资料缺失时也可尝试查询。

## 7. 单次请求与运行时复用

| 机制 | 源码 | 范围与失效 |
| --- | --- | --- |
| 渲染头像／背景／数据 | `checkin/artwork.py` 的 `_render_checkin_card_with_fallback()` | 一次渲染请求只准备一次，三档降级复用；不跨请求缓存下载头像 |
| 刷新背景 data URL | `checkin/shop.py`、`checkin/card.py` | 扣费前验证并编码，渲染时复用；不落盘为长期原图缓存 |
| 签到主题 HTML | `checkin/card.py` 的 `get_checkin_card_template()` | LRU 最多 16 项，含内联 CSS／字体；无 TTL 或 mtime 检测 |
| 日历 HTML | `checkin/calendar.py` 的 `get_checkin_calendar_template()` | LRU 1 项；模块重新加载／显式清理／进程重启后重新拼装 |
| Pixiv 登录状态 | `pixiv/client.py` | refresh token 相同、API 可用且距登录未满 3000 秒时复用；不缓存作品列表或详情响应 |
| HTTP 会话 | 下载器、一言、Lolicon 客户端 | 复用 aiohttp 连接；关闭客户端时释放，不等于缓存 HTTP 响应 |
| 安全规则快照 | `group_safety.py` | 每次请求解析当前配置并合并规则；快照不可变，无自动 TTL |
| 用户请求限频 | `main.py` 的 `_last_request` | 默认同用户 3 秒，配置 0 关闭；只限普通发图频率，不保证选图不重复 |
| 签到／刷新并发锁 | `main.py` 的 `_checkin_flow_lock()` | 同用户流程串行，弱引用保存锁；不是已用图片集合 |
| 一言／AI 警告抑制 | `checkin/greeting.py` | 同原因 warning 最多每 300 秒一次，期间降 debug；不抑制实际请求 |
| Pages 已加载状态 | `pages/pluginCenter/app.js`、`safety.mjs` | 页面内列表、缩略图映射和草稿复用；刷新或业务读写更新，无统一自动 TTL |

### 7.1 下载临时文件

[`pixiv/downloader.py`](../../pixiv/downloader.py) 每次创建 `get_px_*`，没有按 URL 查找旧原图的缓存路径。

- 普通下载、头像、黑名单缩略图和仅供内联的背景源文件，用后清理。
- 普通 OneBot 图片带有效 `message_id` 正常返回、base64 正常返回或构建失败后删除；file 正常返回但无有效 `message_id`、超时、未知或提交期间取消时更新 mtime 并延迟 600 秒删除。即使实际第二次改用 base64，调用方仍可能按 OneBot 路径保护保留原文件。
- 插件关闭取消清理任务，不提前删除受保护文件；初始化扫描插件 temp 的 `get_px_*`，按 mtime 恢复剩余期限。
- 正式签到 JPEG 保存在当天缓存，不按 600 秒删除；付费刷新没有缓存时，file 空回执或超时的渲染文件交给下载器延迟清理。框架 T2I 自身产生的文件不全部位于插件 temp；重启扫描仅覆盖 temp 的 `get_px_*`。
- 600 秒不代表确认送达，不等于图片去重窗口，也不用于正常请求复用旧下载。

### 7.2 节假日与缩略图

[`checkin/holiday.py`](../../checkin/holiday.py) 加载 `holiday_calendar.json` 后在内存查询。初始化后台调用一次 `refresh_if_due()`：插件版本不符、当年缺失、从未成功或成功间隔满 180 天时尝试刷新；最近失败未满 24 小时则不尝试。更新请求当前年与下一年，失败继续用旧数据与本地节日规则。

当前没有循环调度或常驻定时刷新任务；180 天和 24 小时是下次初始化检查时使用的条件，不表示运行中准点刷新。外部修改 JSON 后，已有内存状态也不会自动重读。

黑名单缩略图以作品 ID 关联，原子替换，没有自动 TTL；移除作品黑名单时清理相应缩略图。Pages 的“一键清理缓存”不删除这一目录。

## 8. 排查与维护边界

- 先区分“重复签到复用原卡”“重新选到旧图”“日历允许复用”和“发送延迟”，不要把 JPEG 存在等同于去重生效。
- 核对实际运行的索引天数、北京时间日期、会话 scope、最终 source_key 和原始 illust_id；多个标签是多个池。
- 相同安全规则共享卡片是缓存行为，跨会话允许新选同图是去重行为，两者可以同时成立。
- 修改查询条件时同时核对原子 claim、成功记录、失败 release、旧数据库行和并发回归；只改候选排序不能保证不重复。
- 不为排查清空真实数据库。只读数据库命令见 [开发环境](../dev/setup.md#查看数据库)。Pages 清缓存不会重置 `image_usage`、分页游标、签到奖励、黑名单或备份。
- 本文描述既有实现，不承诺跨会话／跨标签强制去重，也不引入原图哈希或全局用户历史池。验证范围与用例见 [回归入口](../dev/testing.md#缓存复用与去重回归)。

## 9. 其他去重，不属于图片使用索引

- 安全配置按完整 UMO 保证单组归属；全局／组词按 NFKC、大小写与首尾空白判重，保留词内空格和标点。全局作品 ID 规范化为正整数字符串后判重；Lolicon PID 分页都受同一个 ID 约束。这些规则不随 `dedupe_days` 过期，也不改变既有去重 scope。
- 日历事件构建对农历事件及自定义事件使用 `(日期, 名称)` 集合排除重复显示，不是背景去重；在线节假日分支没有完全共用该集合，不能承诺所有来源同名事件都合并。
- Pages 的错误消息集合与列表输入判重只用于显示／编辑；不会建立聊天图片去重记录。
- 发送层遍历异常因果链时用集合避免循环，不是消息幂等键。协议发送没有插件级幂等回执查询，超时停止重发是风险控制，不是已经确认送达。
