# 配置说明

配置真源是根目录 `_conf_schema.json`，按功能分为 6 个 object 分组。AstrBot 配置页以折叠区块呈现，管理中心的「插件配置」提供分组导航、跨组搜索和部分保存。修改字段时同步 README、本文档和相关测试。

管理中心只提交改动的普通字段，不覆盖未改动项；全局安全四键委派到内容安全／安全分组页，隐藏旧键不展示也不能写入。Pixiv Token 与出站代理地址可能包含凭据，读取仅返回是否配置；留空保留，输入新值替换，清除必须显式勾选。保存失败恢复原配置及容器引用，保留页面草稿。设置页不自动重载插件，代理和客户端配置保存后需手动重载；签到奖励规则不变。

重复打开配置页共用在途读取；首次读取失败后重新进入可重试，异常响应不会替换已有配置快照。保存凭据后页面清空输入，仅保留是否配置的状态。下拉选项保留当前已保存的旧值，切换分组后仍可恢复；手机端分组选择标记无效数值，「定位待修正项」会清除搜索并聚焦错误字段。

## 1. Pixiv 图源与下载（`pixiv_source`）

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `pixiv_refresh_token` | `string` | 空 | 使用 Pixiv 作为首选或回退时需要填写；留空直接使用 Lolicon |
| `preferred_image_source` | `enum` | `Lolicon` | 下拉选择 `Lolicon` / `Pixiv`；首选请求失败或无结果时尝试另一源 |
| `lolicon_exclude_ai` | `bool` | `true` | 仅向 Lolicon API 传递 excludeAI=true/false；是否允许混合 R18 由当前会话安全分组的 allow_r18 决定，未分组默认关闭 |
| `lolicon_image_proxy_origins` | `text` | 空 | 每行一个 http(s) origin，最多 5 个按序尝试；仅改写允许列表内 Pixiv 图片主机 |
| `max_count` | `int` | `5` | 单次命令或同条模型消息累计发图上限，范围 1–20；普通模型取图省略 count 时取 1 张，指定作品按目标数执行，默认值不覆盖已保存的配置 |
| `p_coin_cost` | `int` | `20` | 命令和模型工具共用的每张金币，范围 0–200；签到关闭或单价为0时免费；收费时正常返回与发送超时均扣费，下载／构建失败及其他发送异常不扣费 |
| `image_quality` | `enum` | `original` | `original`/`large`/`medium`；固定所选画质，超限／不可用时换作品 |
| `auto_downgrade_original_mb` | `float` | `10.0` | 图片大小上限（MiB），适用于所选画质，范围 0–25；0 关闭软上限；保留旧键并沿用已有数值 |
| `forward_threshold` | `int` | `1` | 命令使用；模型工具仅 send_mode=auto 时使用。下载张数严格大于此值时合并转发（仅 aiocqhttp）；0 始终合并，范围 0–20 |

`preferred_image_source` 保存并重载后生效，普通发图、签到背景与日历背景共用初始请求顺序。Lolicon 有标签时搜索、无标签时随机；Pixiv 有标签时搜索、无标签时推荐。无 Pixiv token 时直接使用 Lolicon；首次请求失败或无结果时尝试可用的另一源。普通取图选定来源后，本请求内保持该来源，Pixiv 沿真实游标续查，Lolicon 有限重抽；单张候选被过滤、去重或下载失败不直接触发换源。有效缓存及已保存背景继续复用，不因切换优先级强制重选。无效选项记录日志并使用默认 Lolicon 优先。

普通发图先用同批剩余候选补足张数，每次请求最多取 3 批、实际尝试 20 张作品，同一作品 ID 不重复下载。大小等于上限可发送；超限、所选画质地址缺失或下载失败则换图，不尝试其他画质。反代与源地址重试保持同一画质。跳过候选清理文件并释放临时占用，最终按实际发送调用结果结算；不足时发送已找到的图片。签到和日历仍使用独立画质规则，不应用此软上限。

同一用户跨消息的收费取图从余额检查到结算清理结束期间，其他指令／模型收费取图直接返回繁忙，不排队、不扣费、不消耗模型发图名额，也不自动重试。免费取图、其他用户及同消息内原有多任务串行规则保持各自行为。

命令在首次取源与候选过滤完成后建立下载及候选补取预算：`request_timeout × max(3, 实际执行张数)` 秒；张数取应用数量上限后的值，默认超时 30 秒时，1 张为 90 秒、5 张为 150 秒。首次取源、消息发送和资源清理不计入这段选图预算。模型工具从框架工具超时中预留一半（最多 30 秒）给发送、结算和清理，首次取源也受剩余预算限制；后续下载和补取取框架选图截止时间与上述下载阶段截止时间中较早者，张数还受余额限制。预算到期取消进行中的网络操作，发送已下载图片，允许少于执行张数；该预留不是完成时限保证。大小上限在响应头及分块读取时执行。

旧阈值不会自动改为 10 MiB；使用原图且频繁因大小限制换图时，建议手动将上限调整为 10 MiB。

Lolicon 请求地址固定为 `https://api.lolicon.app/setu/v2`。旧 `lolicon_api_url` 从 schema 删除，由 AstrBot 加载时裁剪；简单 dict 中的残留值也不参与请求，旧自定义地址和留空停用不再生效。图片反代 origin 配置仅改写图片地址；连接出口另由 `network_proxy_url` 与 `network_proxy_mode` 控制。

OneBot 发图默认使用本地 `file:///` 路径；仅在明确文件读取失败（包括协议端“路径不存在”）时，将同一条消息回退到 base64 编码重试一次，超时不回退、不重发。base64 是图片编码，与 AstrBot 4.27.3 的 OneBot 默认发图编码相同；回退仍直接调用 OneBot，不额外尝试 AstrBot 框架发送。file 发送正常返回但没有有效 `message_id` 时仍扣费，并保留图片 10 分钟供协议端读取，不重发。旧 `onebot_image_transport`（顶层及 `pixiv_source` 内）由 AstrBot 在加载时按 schema 裁剪；插件不依赖旧键，也不能恢复框架已裁剪的值。发送异常仅记日志，详见 [发送流程](architecture.md#onebot-图片发送)。

### Lolicon 图片反代

Lolicon API 返回作品信息和各档图片 URL，插件筛选后直接下载；图片反代只替换 URL 的协议和主机，保留作品路径与画质档位，不重新选图、不负责提高画质，也不决定连接出口。配置出站代理后，反代地址同样通过该代理下载。

在 `lolicon_image_proxy_origins` 中**一行一个完整 origin**，最多 5 个，按填写顺序尝试；不可用再尝试 API 返回地址，受单图总共 8 次下载预算限制。只填协议、域名和可选端口，不填路径、作品 ID 或 `{{path}}`；保存后重载。只对 Lolicon 来源且位于支持列表中的图片主机改写。

以下为原文保留的历史测试记录，不代表当前可用性。

| 地址 | 服务方地区建议 | 当时本机直连 | 当时本机走海外 HTTP 代理 |
| --- | --- | --- | --- |
| `https://i.pixiv.re` | 大陆优先，海外也可尝试 | 下载中途超过 30 秒 | 成功，2.09 秒 |
| `https://i.pixiv.nl` | 大陆备用，海外也可尝试 | 下载中途超过 30 秒 | 下载中途超过 30 秒 |
| `https://i.pixiv.cat` | 海外优先，大陆直连不推荐 | HTTP 500 | HTTP 500 |
| `https://i.muxmus.com` | 未明确限制地区，需实测 | 成功，10.54 秒 | 成功，3.98 秒 |

地区建议来自 [Pixiv.cat 反代说明](https://pixiv.cat/reverseproxy.html)；[木辛木杉服务](https://i.muxmus.com/) 提醒节制使用、不要用于爬虫。公共服务可能限速或停服，请使用可信服务；旧教程中的 `i.yuki.sh` [已停止服务](https://blog.yuki.sh/posts/599ec3ed8eda/)。

### 出站代理

在 `runtime.network_proxy_url` 填写 `http://127.0.0.1:10808`、`socks5://127.0.0.1:10808` 或 `socks5h://127.0.0.1:10808`，保存并重载。须包含主机和 1–65535 端口，不含路径、查询或片段；可带账号密码，保留字符须百分号编码。SOCKS5 使用代理端 DNS，`socks5h` 规范化为 `socks5`。不支持 `https://` 代理服务器，但 HTTP 代理可承载 HTTPS 网站请求。

| 插件请求 | 全部走代理 | Lolicon API 不走代理 |
| --- | --- | --- |
| Pixiv OAuth、Token 刷新及全部 App API | 代理 | 代理 |
| Pixiv 公开热度 | 代理 | 代理 |
| `https://api.lolicon.app/setu/v2` | 代理 | 直连 |
| 全部图片、Lolicon 图片反代与 QQ 头像下载 | 代理 | 代理 |
| 一言、GitHub 节假日数据 | 代理 | 代理 |

代理地址为空时上述请求均按旧行为直连，模式不影响出口。不读取或修改 `HTTP_PROXY`、`NO_PROXY` 或 AstrBot 全局代理；配置格式或模式无效时拒绝加载，不静默切成直连。代理网络失败沿用原失败／换源流程，不做出站直连回退；图片反代与图源切换后的请求仍遵守各自路由。

“全部”仅指插件自有网络请求。OneBot、模型提供商、AstrBot T2I 与管理页面浏览器请求仍由各自配置管理。系统 TUN／透明代理不受此开关控制。Docker 中的回环地址是容器本身，请使用容器内可达地址；仅使用可信代理，不在日志中记录代理凭据。依赖 `aiohttp-socks==0.12.0`，其要求 `aiohttp>=3.10`、`python-socks[asyncio]>=2.4.3,<4`，兼容核心环境中的 `python-socks 3.2.1`。遇到核心依赖保护冲突时使用兼容的插件版本，不降级核心依赖或绕过保护。

## 会话内容安全策略

安全配置统一位于 `content_dedupe`；配置页与 Pages 修改同一份配置，不再从 SQLite 读取运行时关键词／黑名单。

每个 `safety_groups` 条目包含 `name`、`sessions`、`allow_r18=false`、`custom_terms=[]`。隐藏 `group_id` 由服务生成并持久化，只用于稳定编辑身份。`sessions` 使用 `/sid` 返回的完整 `平台实例:消息类型:会话ID`；一个 UMO 只能归属一个分组，不猜测裸群号／用户号对应哪个 Bot。

管理中心新建、编辑共用居中弹窗，会话和附加词按行输入，R18 默认关闭。窄屏可滚动，操作栏保留在底部；保存失败保留草稿，放弃未保存修改前确认。

- 未分组或无会话上下文：全局规则＋R18 关闭。有效分组：全局词＋组词，全局作品 ID 黑名单始终生效。
- 只有一个全局匹配模式。宽松匹配完整原标签与翻译标签；严格另外匹配标题子串。查询词在宽松模式完整匹配、严格模式按子串预检；均不执行正则／通配符、不检查简介。
- NFKC、casefold、首尾空白规范化；词内空格、连字符等分隔符不删除。关键词最多 64 字符；作品 ID 必须为 ASCII 正整数文本，前导零归一化。
- 分组 R18 开启表示允许混合分级候选，不是只检索 R18。分级、词、ID 同时校验；规则读取／校验失败拒绝请求。
- 旧群／私聊编辑和批量复制 API 已删除。保存失败恢复内存配置及列表引用，后续请求不使用未保存草稿。

## 升级基线

v3.8.8 移除固定句式发图及 `auto_trigger_enabled` 开关，旧键由 AstrBot 按 schema 在加载时清除。聊天取图改用模型原生工具；消息需进入模型对话且工具可用，不使用模型时仍可用 `/p`。纯文本「签到」保留。

配置升级基线仍为已完成迁移的 v3.8.0，顶层仅保留六个正式分组。旧小时去重与扁平配置迁移不恢复。`content_dedupe` 中隐藏保留旧 `group_content_safety_policies`、`private_content_safety_policies` 和旧迁移标记，仅供归档；旧模板和运行逻辑已删除。不能先删桥接键：AstrBot 在插件初始化前会裁剪 schema 外字段。

首次初始化按内容哈希原子写入 `safety_legacy_backups/legacy-<sha256>.json` 并读回核对，归档旧配置、历史数据库策略、全局词及作品元信息。核对成功才保存版本 1 并清空旧配置列表；失败停止加载，不猜 UMO 或继承旧 R18。旧全局人工词与作品 ID 合并进新配置，旧局部列表只归档。版本 1 后不再读旧来源，删除的新规则不会重载复活。SQLite 历史策略表保留为只读历史，schema3 在配置保存后经备份收敛回 v2，不删除签到或金币数据。

图片索引另有一次性重置：本版首次加载时清空全部图片使用／占用记录（含签到背景）和分页键，正式签到数据、安全规则和卡片缓存保留。完成标记与清理在图片索引库的同一事务中持久化；不新增配置开关，之后保存配置、重载或重启均不重复清空。恢复没有标记的旧索引库会重新触发，详见[缓存与去重](cache-and-dedupe.md#21-索引身份)。

管理中心数据导出包含 `checkin`、`safety`、`blacklist_metadata` 和 `legacy_safety_archives`，不包含凭据。导入包只恢复签到并提前创建回滚备份；当前安全配置及旧档案均不导入。旧签到 JSON 仍可导入，旧安全档案不能单独恢复。

导入成功后重新读取成员列表，并保留当前搜索和页码；导入前尚未完成的旧读取不能覆盖恢复后的数据。全局匹配方式保存成功后立即更新页面状态，与安全分组保存同时进行时也保持一致。

升级前备份插件配置 JSON 和数据目录。早于 v3.8.0 的版本须先安装 v3.8.0、成功启动，并确认自定义值及群／私聊策略已保存到对应分组后再升级。仅存在于顶层的值不属于支持范围；AstrBot 4.27.3 在插件初始化前删除 schema 外的键，插件无法在裁剪后找回旧值。若来自 v2.8.x 或已有数据但数据库无 schema 版本号，先使用 v3.0.0 完成签到数据迁移，再经过 v3.8.0 完成配置迁移。不要先升级再依赖回退旧版本恢复配置。

## 配置维护规则

- README 配置表必须和 `_conf_schema.json` 保持一致。
- 运行时通过 `main.py` 的 `_cfg_str`/`_cfg_int`/`_cfg_float`/`_cfg_bool` 读取。正式配置由 AstrBot 按分组加载；读取层保留简单 dict 支持，但不承担旧扁平配置迁移。不要在业务流程散落 `self.config.get(...)`。
- 分组后存盘为嵌套 `config[组][键]`；新增配置项时加入对应组的 `items`，读取层无需改动。
- 删除、重命名或改字段类型时必须说明兼容影响。
- `forward_threshold` 按下载张数判断，仅 aiocqhttp 合并转发；旧 `send_as_forward` 仅在新字段缺失时兼容（`true`→0，`false`→20）。
- `content_dedupe.dedupe_days` 已从 schema 移除，框架加载时裁剪旧键；运行时不再读取旧值。历史行沿用原表并按新窗口筛选，不新增数据库 schema。
- `image_quality` 不影响签到背景，签到卡/日历背景画质由 `checkin_card_quality_tier` 独立控制。
- `pixiv_refresh_token` 留空时跳过 Pixiv，仅请求 Lolicon；失败或无结果时不再有可用回退源。
- schema 顶层仅定义六个正式分组。安全服务只读写 `content_dedupe`；嵌套旧桥接键仅归档，空列表不恢复已停用的顶层策略。

## 模型取图参数

`/p` 统一随机及组合搜索，复用图源优先级；`/pd` 指定作品单页、`/pr` 榜单固定使用 Pixiv。三者和模型工具共用领域执行，沿用命令账单与合并阈值，不新增配置。`/ps` 已移除。

v3.8.8 新增的出站代理配置由管理员设置，不暴露为模型工具参数。原生工具沿用 `max_count`、`p_coin_cost`、`checkin_enabled`、图源、画质、大小上限和当前完整 UMO 安全分组。模式、目标、数量、发送及筛选参数仅作用于本次工具调用，完整约束见 [随包 Skill](../../skills/get-px-image/SKILL.md)。默认 `single`；`auto` 才使用 `forward_threshold`，`forward` 仍受 OneBot 平台能力限制。

模型工具数量结果中，`requested_count` 是请求数量，`effective_count` 是应用配置及余额限制后的执行数量，`max_count` 是本次读取的上限，`count_limits` 列出 `max_count`／`balance`（可同时存在）。缩减原因通过 `notice` 说明；实际候选不足另由 `message` 说明，均不代表标签失效。搜索日志分别记录原始请求数、实际执行数与配置上限。

`tag` 整串最多48字符，空格表示 AND。`search` 固定 Pixiv，`auto` 与 `/p` 按来源适配同样的组合条件；Lolicon 最多3个条件，超出时只尝试可用的 Pixiv，不丢弃条件。尺寸和比例使用独立参数。

模型工具默认逐张直发，仅 `send_mode=auto` 读取合并阈值。比例容差省略时使用 `min(0.1, aspect_ratio/2)`，显式传入仍须非负且小于目标比例，0 表示精确比例。

公开作品与作者查询免费，不读钱包、不下载、不占去重，独立使用现有限频秒数；同事件允许查询后发送。默认模式沿用两源顺序，其余明确模式只使用 Pixiv，不因失败回退到 Lolicon。推荐基于配置账号，未联网验证的配置状态不证明 token 有效。查询游标仅保留在内存，不新增持久配置或数据库表；续查、失效和单页目标规则见随包 Skill。

作品查询可传 `include_stats=true` 按需补查点赞、收藏和浏览量，默认 false，不是持久配置。只补查本批安全过滤后的候选，最多20个作品、并发3个，共用至多3秒的剩余查询预算；失败返回候选与已有统计，缺失计数为 null。普通发图、签到与日历不增加热度请求。游标继承原选项，续查只传 cursor。

模型同消息的不同取图任务串行执行，累计提交张数共享 `max_count`；仅首次发送检查用户限频，后续任务不刷新消息等待预算。已提交、已受理或送达未知均占用本消息名额；确定未提交的失败不消耗名额，可按工具提示重试。
