# 维护规则

本文面向维护者和协作 agent，记录开发时需要遵守的仓库级规则。业务细节不要继续塞进 `AGENTS.md`，应拆到 `docs/project/` 的对应主题文档。

## 文档同步

- 文档不是可选收尾。
- 行为、边界、入口、配置、流程、架构或维护约定变化时，必须同步更新对应文档。
- 下列变化默认需要更新文档：
  - 指令行为或参数变化
  - 配置项、默认值或兼容规则变化
  - 签到奖励规则、商店商品或卡片渲染逻辑变化
  - 发图流程、质量策略、过滤规则或去重逻辑变化
  - 下载器返回值、反代配置或降级策略变化
  - 数据库 schema、存储路径或清理规则变化
  - 测试或验证流程变化
- 修改 repo-wide 维护规则或 agent 入口约定时，同步更新 `AGENTS.md`。

## 入口与模块边界

入口与模块事实统一维护在 [`../project/architecture.md`](../project/architecture.md)。本文件只记录维护要求：不要把复杂业务逻辑重新塞回 `main.py`。

`main.py` 只负责：
- AstrBot 生命周期
- 指令装饰器注册
- 配置读取
- 领域对象装配

业务逻辑放在：
- `checkin/` - 签到相关
- `pixiv/` - Pixiv 作品获取相关
- `plugin_api/` - Plugin Pages 后端 API

## 本地路径

- 插件数据目录由 AstrBot `StarTools.get_data_dir("astrbot_plugin_get_px")` 提供。
- 不要在插件目录创建或依赖 `<plugin>/data` 作为运行态目录。
- 签到数据、去重索引、黑名单、节假日缓存都保存在插件数据目录中。

## 配置维护

- 配置字段语义见 [`../project/configuration.md`](../project/configuration.md)。
- `_conf_schema.json` 字段新增、删除、重命名或类型变化时，必须同步 README、配置文档和相关回归测试。
- 不在维护文档里复制完整配置表。
- 配置读取统一通过 `main.py` 的方法访问，不要在业务流程中散落调用 `self.context.get_config(...)`。

## 测试与检查

常用命令见 [`testing.md`](./testing.md)。涉及下列行为时，优先补回归测试：

- 下载器返回值变化
- 签到奖励规则变化
- 去重索引逻辑变化
- 内容安全过滤规则变化
- 配置字段兼容性变化
- 数据库 schema 迁移
- Lolicon 反代轮换逻辑
- 签到卡片渲染流程

## 数据库维护

- 签到数据使用 `checkin.sqlite3`，包含用户资料、奖励记录、群排行、卡片缓存、事件、称号、节假日缓存。
- 去重索引使用 `image_index.sqlite3`，包含作品去重、安全词、作品黑名单。
- Schema 变化必须提供迁移逻辑（`checkin/schema.py`）。
- 迁移前自动创建备份，失败时可回滚。
- 不要在插件启动时直接删除或重建数据库。
- 临时配置迁移表（例如 schema3 的 `group_content_safety`）不得单独占用正式 schema 版本；迁移必须先保存配置，再通过 SQLite backup API 记录备份，最后只更新 `user_version`，保留历史表与数据。

## 进度记录

- 开发任务使用 `Progress/` 目录记录。
- 文件按日期命名：`Progress/YYYY-MM-DD.md`。
- 同一天多个任务使用序号：`Progress/YYYY-MM-DD-01.md`。
- 记录内容：任务需求、实现清单、当前状态、改动文件、遇到的问题、重要决策、未解决的风险。
- 进度记录是改动的一部分，不是可选文档。

## Git 规范

- 提交信息第一行简明扼要（50 字以内）。
- 详细说明改动原因、影响和验证方式。
- 不要在提交信息中添加 AI 归属（如 `Co-Authored-By: Claude`）。
- 小步提交，单次改动围绕一个目的。
- 提交前运行语法检查和相关测试。

## 已移除或不属于本插件的能力

本插件不维护以下能力，修改相关入口前先确认是否真的属于本插件职责：

- 通用 Pixiv 浏览器或作品详情页
- 长期存储完整作品元数据
- 实时监控 Pixiv 作者动态
- 跨机器同步签到数据
- 独立 Web 服务（Plugin Pages 是 AstrBot 内置的管理界面）

## 重要约定

- 下载器 `download()` 返回 `(path, size)` 元组，所有调用方必须解包。
- Lolicon 反代配置最多解析前 5 个有效 origin。
- 签到卡片缓存只保留一天，跨天自动失效。
- 去重索引按 `dedupe_days` 保留最近 N 个自然日。
- 内容安全过滤支持通配符和敏感度配置。
- 节假日数据每 180 天自动更新一次。
- 签到主题价格可配置为 0（免费），但仍需完成购买记录所有权。
- 签到问候支持三种模式：本地事件、一言 API、AI 模型。

## 破坏性改动注意事项

以下改动属于破坏性改动，必须特别小心：

- 修改 SQLite schema（必须提供迁移逻辑）
- 修改配置字段类型或默认值（必须提供兼容方案）
- 修改下载器或关键 API 返回值类型（必须更新所有调用方）
- 修改签到奖励规则（必须考虑对现有用户的影响）
- 修改去重索引逻辑（可能导致重复发图或漏图）
- 修改内容安全过滤规则（可能导致误杀或漏过）

破坏性改动必须：
1. 在 CHANGELOG 中明确标注
2. 提供迁移指南或兼容方案
3. 补充充分的测试覆盖
4. 更新相关文档
# 内容安全与数据库迁移约束

- 群聊与私聊策略是配置文件中的 config-backed 模板列表，字段定义必须同步维护 `_conf_schema.json`、README、配置文档和 WebUI。
- 修改签到数据库 schema 时递增 `CHECKIN_DB_SCHEMA_VERSION`，兼容已知旧版本，并在执行 DDL 前使用 SQLite backup API 写入 `checkin_migration_backups/`。临时配置迁移表不递增正式版本；schema3 收敛必须在配置保存成功后备份并只更新 `user_version`，不得删除历史表或行。
- 配置 schema 由 `pixiv_source`、`content_dedupe`、`checkin_omnidraw`、`checkin_basic`、`checkin_shop`、`runtime` 六组组成；旧扁平键通过 `_CONFIG_KEY_TO_GROUP` 迁移，内容安全策略模板正式位于 `content_dedupe.items`，顶层仅保留 invisible 兼容键。
- 会话策略服务以根配置对象调用 `save_config()`，但优先读写 `content_dedupe` 嵌套容器；迁移、重载、批量保存失败时必须恢复嵌套对象身份和兼容键内容。
- 内容安全调用链必须复用一次请求解析得到的 `ContentSafetyPolicy`：策略开启“启用内置安全词”时使用内置安全词、内容安全页的全局自定义屏蔽词与作品 ID 黑名单，并忽略当前会话的独立列表；关闭时停止前三类全局约束，仅使用当前会话的独立自定义屏蔽词与独立作品 ID 黑名单。
- 独立列表分别归属于每条群聊或私聊策略；批量应用只覆盖对应字段、只作用于当前已有策略，并在一次保存中完成，任一失败都回滚本次批量变更。
- 没有会话上下文、策略缺失或读取策略异常时严格默认普通分级与内置安全词均开启。
